# pysrat-experiments

This repository contains experiment setups and outputs for fault prediction at the module level.

## Target Projects

### PX4

```bash
git clone --branch v1.16.1 https://github.com/PX4/PX4-Autopilot.git
```

- Target directory: `PX4-Autopilot/src`
- Commit period: from `2013-W08` to `2025-W37`
- Target period: from `2016-W06` to `2025-W37` (`500` weeks)

### Airflow

```bash
git clone --branch 2.11.1 https://github.com/apache/airflow.git
```

- Target directory: `airflow/airflow`
- Commit period: from `2014-W42` to `2026-W07`
- Target period: from `2016-W28` to `2026-W07` (`500` weeks)

### Linux

```bash
git clone https://github.com/torvalds/linux.git --branch v6.12
```

- Target directory: `linux/drivers/net`
- Commit period: from `2005-W15` to `2024-W46`
- Target period: from `2015-W16` to `2024-W46` (`500` weeks)

## Data Preparation

Each experiment directory (e.g., `px4-experiments/`, `airflow-experiments/`, `linux-experiments/`) contains analysis outputs generated using [code-analysis](https://github.com/SwReliab/code-analysis).

### Generated Files

The following files are generated by `code-analysis` and used in the experiments:

- `group_embeddings.jsonl`: Module embedding vectors generated from code structure
- `commits_by_module_week.csv`: Number of commits per module per week
- `lizard.csv`: Metrics from Lizard code analysis (complexity, lines of code, etc.)
- `module_metrics.csv`: Various module-level metrics (fan-in, fan-out, etc.)
- `analysis.yaml`: Configuration file for code analysis settings

### Generating Fault Data

To run the experiments, you need to generate the `faultdata` directory using the following command:

```bash
cd {experiment_dir}  # e.g., px4-experiments, airflow-experiments, or linux-experiments
code-analysis faultdata -c analysis.yaml --execute
```

This command generates fault data from git commit history and must be executed before running the experiment scripts (`runall_offset_*.py`).

## Experiment Settings

### Common

- Target variable: number of faults per module
- Offset: `log(sum_nloc / 1000)`
- Use `sum_nloc` converted to KLOC
- Train and evaluate at the project level
- Alpha values for regularized models:
- `elastic net`: `alpha = 0.5`
- `random effect only`: `alpha = 0` (L2 regularization only)

### Embedding-Based Methods

Models using module embedding representations.

1. `PCA (embedding vector) + elastic net` (runall_offset_embpca.py, res_offset_embpca.txt, result_prediction_offset_embpca.csv)
	- Apply PCA to embeddings
	- Use the minimum number of principal components that reaches 95% cumulative explained variance
	- Cap the dimension at $\lfloor n/5 \rfloor$ where $n$ is the number of modules
2. `Kernel (Gram matrix) + L2 regularization` (runall_offset_embkernel.py, res_offset_embkernel.txt, result_prediction_offset_embkernel.csv)
	- Use the kernel matrix as input
	- Apply L2 regularization

### Metrics-Based Methods

Models using metrics other than `sum_nloc`.

1. `Metrics + elastic net` (runall_offset_metrics.py, res_offset_metrics.txt, result_prediction_offset_metrics.csv)
    - Use metrics excluding `sum_nloc` as inputs
    - No dimensionality reduction
    - Apply elastic net regularization
2. `PCA (metrics vector) + elastic net` (runall_offset_metpca.py, res_offset_metpca.txt, result_prediction_offset_metpca.csv)
	- Use metrics excluding `sum_nloc` as inputs
	- Use the minimum number of PCA components that reaches 95% cumulative explained variance
	- Cap the dimension at $\lfloor n/5 \rfloor$
    - Apply elastic net regularization
3. `Kernel (Gram matrix) + L2 regularization` (runall_offset_metkernel.py, res_offset_metkernel.txt, result_prediction_offset_metkernel.csv)
    - Use the kernel matrix of metrics excluding `sum_nloc` as input
    - Apply L2 regularization (alpha = 0)

### with Smoothing

1. `Random effect (identity kernel) only` (runall_offset_identity.py, res_offset_identity.txt, result_prediction_offset_identity.csv)
    - Use the identity kernel for the random effect
    - Apply L2 regularization (alpha = 0)
2. `Random effect (embedding kernel) only` (runall_offset_id_embkernel.py, res_offset_id_embkernel.txt, result_prediction_offset_id_embkernel.csv)
    - Use the embedding kernel for the random effect
    - Apply L2 regularization (alpha = 0)
3. `Random effect (metrics kernel) only` (runall_offset_id_metkernel.py, res_offset_id_metkernel.txt, result_prediction_offset_id_metkernel.csv)
    - Use the metrics kernel for the random effect
    - Apply L2 regularization (alpha = 0)
4. `Metrics (no constraints) + random effect (identity kernel)` (runall_offset_metrics_re.py, res_offset_metrics_re.txt, result_prediction_offset_metrics_re.csv)
    - Use metrics excluding `sum_nloc` as inputs
    - Apply L2 regularization (alpha = 0) only for the random effect with the identity kernel
5. `Metrics (no constraints) + random effect (embedding kernel)` (runall_offset_metrics_embkernel_re.py, res_offset_metrics_embkernel_re.txt, result_prediction_offset_metrics_embkernel_re.csv)
    - Use metrics excluding `sum_nloc` as inputs
    - Apply L2 regularization (alpha = 0) only for the random effect with the embedding kernel

## Environment Setup

### Requirements

- Python 3.9 or later
- Git

### Installation

1. Clone this repository:
```bash
git clone <repository-url>
cd pysrat-experiments
```

2. Create a virtual environment:
```bash
python3 -m venv venv
source venv/bin/activate
```

3. Install dependencies:
```bash
pip install -r requirements.txt
```

### Key Dependencies

- `pysrat`: Core NHPP (Non-Homogeneous Poisson Process) model library
- `code-analysis`: Code analysis toolkit for generating module metrics and embeddings
- `pandas`, `scikit-learn`, `numpy`: Data processing and machine learning
- `joblib`: Serialization and result caching
- `torch`: Optional, used in `vae.py` for VAE-based embedding compression (not used in current experiments)

## Running Experiments

### Step 1: Prepare Data (One-time Setup)

For each project directory, generate fault data:

```bash
cd px4-experiments  # or airflow-experiments, linux-experiments
code-analysis faultdata -c analysis.yaml --execute
```

This step is required before running any experiment scripts.

### Step 2: Run Experiment Scripts

Navigate to the experiment directory and run desired experiment(s):

```bash
cd px4-experiments
python ../scripts/runall_offset_embpca.py      # PCA embedding experiment
python ../scripts/runall_offset_embkernel.py   # Kernel embedding experiment
# ... repeat for other runall_offset_*.py scripts
```

Each script:
- Caches intermediate results to `cache_offset_*/` directories
- Generates results summary to `res_offset_*.txt`
- Outputs predictions to `result_prediction_*.csv`

### Step 3: Extract and Verify Results

```bash
cd px4-experiments
python ../scripts/extract.py cache_offset_embkernel --model best --view all --output csv > result_prediction_offset_embkernel.csv
```

Or use the batch extraction script:

```bash
bash ../scripts/extract_all.sh
```

### Running All Experiments at Once

To run all experiment scripts sequentially:

```bash
cd {experiment_dir}
bash ../scripts/run.sh  # Executes all runall_offset_*.py scripts
```

This script runs all 10 experimental methods and saves results to `res_offset_*.txt` files.

## Output Files Description

### Experiment Results (res_offset_*.txt)

- Contains summary statistics for each experimental method
- Includes:
  - Model parameters (alpha values, dimensions used)
  - Training/validation performance metrics
  - Optimal hyperparameters
  - Execution time

### Prediction Results (result_prediction_*.csv)

- CSV files with module-level predictions
- Columns:
  - `module`: Module identifier
  - `step`: Time step (week)
  - `actual`: Actual fault count
  - `predicted`: Model prediction
  - `error`: Abs(actual - predicted) or other error metric
  - Additional columns depend on extract parameters

## Reproducibility Notes

### Fixed Parameters

- **Python version**: 3.9+
- **PCA variance threshold**: 95% cumulative explained variance
- **Dimension cap**: ⌊n/5⌋ where n = number of modules
- **Train/test split**: Temporal split at time `t0` (specified in analysis.yaml)
- **Offset constant**: `log(sum_nloc / 1000)` (KLOC)

### Sequential Dependency

1. Data preparation is **required before** running experiments (`code-analysis faultdata`)
2. Experiments can be run in any order independently
3. Result extraction depends on completed experiments

### Randomness

- **OpenAI embedding generation**: Module embedding vectors are generated via OpenAI API. These are deterministic given the same model and input code, but API versioning or model updates could affect reproducibility.
- **Cross-validation splits**: Deterministic based on time steps
- **Kernel computations**: Deterministic
- **Model fitting**: Deterministic given fixed random seed (if applicable)
